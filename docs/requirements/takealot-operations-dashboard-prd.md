# Takealot 单品流量与销量运营系统 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | Takealot 单品流量与销量运营系统 |
| 文档类型 | 产品需求文档（PRD） |
| 版本 | 1.0 |
| 日期 | 2026-07-20 |
| 部署方式 | Windows 本地运行 |
| 数据库 | 本机 MySQL 8.0，统一保存店铺、指标与竞品数据 |
| 主要用户 | Takealot 店铺运营人员、运营负责人 |

## 2. 背景

运营人员需要直观查看每个产品的流量与销量变化，并能把结果分享给其他人员。

Takealot Seller API 可以提供按销售明细记录的销量数据，以及 Offer 维度的近 30 天浏览量和转化率。但是，API 不提供精确的单品每日浏览量或每日访客数。因此，产品必须明确区分精确指标、滚动窗口指标和派生指标，不能把 30 天窗口差值误标为每日流量。

本系统采用“一份数据、多种输出”的方式，同时解决本地网页可视化强、文件分享方便两个需求。

## 3. 产品目标

### 3.1 核心目标

1. 每天自动采集 Takealot 商品和销售数据，并保留历史记录。
2. 让运营人员通过本地网页直观查看店铺、单品和异常趋势。
3. 自动生成可分享的离线 HTML、Excel 和 PNG 日报。
4. 所有展示端使用同一套数据和指标计算规则。
5. 清楚标识流量数据的真实口径，避免将 30 天滚动指标误解为精确日流量。

### 3.2 成功标准

1. 运营人员可以在 30 秒内找到任意 SKU 并看到其销量和流量趋势。
2. 每日销量、销售额在网页、HTML、Excel 中保持一致。
3. 每日任务完成后，自动生成当日 HTML、Excel 和 PNG 文件。
4. 离线 HTML 在断网状态下可直接打开并使用核心筛选和图表。
5. Excel 无需宏即可打开、筛选和查看图表。
6. 未知销售状态、API 拉取失败和数据缺失不会被静默忽略。

## 4. 非目标

第一版不包含以下内容：

1. 云端部署、互联网公开访问或多租户账号体系。
2. 自动修改商品价格、库存、Offer 状态或其他 Takealot 数据。
3. 广告投放、流量来源、关键词排名和搜索曝光分析。
4. 将近 30 天浏览量差值伪装成精确每日浏览量。
5. 企业微信、邮件或其他平台的自动发送。
6. 手机原生应用。

## 5. 已确认的 API 能力

官方文档地址：<https://marketplace-api.takealot.com/v1/docs>

### 5.1 Offers

使用 `GET /offers` 获取商品当前状态和近 30 天运营指标。

第一版读取字段：

- `offer_id`
- `tsin_id`
- `sku`
- `barcode`
- `title`
- `selling_price`
- `rrp`
- `benchmark_price`
- `status`
- `image_url`
- `productline_id`
- `conversion_percentage_30_days`
- `conversion_percentage_previous_30_days`
- `page_views_30_days`
- `quantity_returned_30_days`
- `total_wishlist`
- `wishlist_30_days`
- `listing_quality`
- `discount_percentage`
- `updated_at`

按需展开：

- `seller_warehouse_stock`
- `takealot_warehouse_stock`
- `offer_charges`

`GET /offers` 默认每页 100 条，最大每页 1000 条，使用 `continuation_token` 翻页。

### 5.2 Sales

使用 `GET /sales` 获取销售明细。

第一版读取字段：

- `order_item_id`
- `order_id`
- `order_date`
- `sale_status`
- `offer_id`
- `tsin_id`
- `sku`
- `selling_price`
- `quantity`
- `success_fee`
- `fulfillment_fee`
- `courier_collection_fee`
- `total_fees`
- `stock_transfer_fee`
- `sales_region`
- `stock_source_region`

日期筛选使用 `order_date__gte` 和 `order_date__lte`，口径为南非标准时间 SAST。每页最大 100 条，使用 `continuation_token` 翻页。

当前官方文档没有给出 `sale_status` 的固定枚举，也没有提供销售状态筛选参数。系统必须保存原始状态，并对未知状态进行提示。

### 5.3 辅助接口

第一版预留但不作为核心页面依赖：

- `GET /returns`：退货日期、数量、原因、处理结果和客户备注。
- `GET /transactions`：财务流水；最大查询区间 180 天，默认最近 30 天。
- `GET /shipments`：发货和补货信息。
- `GET /balances`：账户余额与放款信息。
- `GET /seller`：卖家账户信息。

### 5.4 当前不支持的指标

Seller API 当前没有提供：

- 单品每日浏览量。
- 单品每日独立访客数。
- 店铺每日浏览量或访客数。
- 流量来源。
- 实时访客。

第一版不得用推算值冒充上述指标。

## 6. 指标定义

### 6.1 精确指标

| 指标 | 计算规则 | 时间口径 |
|---|---|---|
| 下单件数 | 按 SKU、SAST 日期汇总 `/sales.quantity` | SAST |
| 下单金额 | 按销售明细汇总 `selling_price × quantity` | SAST |
| 订单行数 | 去重统计 `order_item_id` | SAST |
| 订单数 | 去重统计 `order_id` | SAST |
| 费用 | 汇总 API 返回的各费用字段 | SAST |
| 退货件数 | 按 SKU、`return_date` 汇总退货数量 | API 日期 |

### 6.2 销售状态口径

系统同时保留以下两套销量指标：

1. `下单件数`：所有 `/sales` 记录的数量总和，不根据状态排除。
2. `有效销售件数`：根据本地状态规则表计算。

首次成功拉取销售数据后，系统生成实际出现的 `sale_status` 清单。状态规则存放在 `config/sale_status_rules.yaml`：

- `included`：计入有效销售。
- `excluded`：不计入有效销售。
- `unknown`：未知状态，不计入有效销售，并在数据质量页面报警。

在状态规则尚未确认前，页面主指标显示“下单件数”，不显示“有效销售件数”。

### 6.3 流量指标

| 展示名称 | 计算规则 | 性质 |
|---|---|---|
| 近 30 天浏览量 | `page_views_30_days` | API 原始值 |
| 近 30 天日均浏览量 | `page_views_30_days / 30` | 派生平均值 |
| 30 天浏览量窗口净变化 | 今日值减昨日值 | 趋势参考值 |
| 近 30 天转化率 | `conversion_percentage_30_days` | API 原始值 |
| 上一周期转化率 | `conversion_percentage_previous_30_days` | API 原始值 |
| 转化率周期变化 | 本周期转化率减上一周期转化率 | 派生指标 |

系统所有页面和导出文件必须使用上述名称。不得将“近 30 天日均浏览量”写成“昨日流量”，不得将“窗口净变化”写成“每日流量”。

### 6.4 库存指标

库存指标来自 Offer 展开数据，按仓库和区域保留原始库存。第一版展示：

- 卖家仓库存量。
- Takealot 仓库存量。
- 总可见库存。
- 库存状态。
- 连续无库存天数。

## 7. 产品形态

系统包含一个本地网页和三种共享输出，四者共用 MySQL 数据库与统一指标层。

### 7.1 本地网页看板

默认只监听 `127.0.0.1`，不开放局域网访问。

页面包括：

1. 店铺总览。
2. 单品分析。
3. 经营四象限。
4. 异常商品清单。
5. 数据质量与采集状态。
6. 导出中心。

### 7.2 离线 HTML

每日生成单文件 HTML 报告，图表脚本和当日数据全部内嵌，不依赖服务器或外部网络。

离线 HTML 支持：

- SKU、Offer ID 和商品名称筛选。
- 时间范围切换。
- 图表悬停提示。
- 商品异常标签筛选。
- 单品趋势查看。

离线 HTML 是数据快照，不包含 API Key，不提供写入或刷新功能。

### 7.3 Excel 日报

Excel 文件不使用宏，包含以下工作表：

1. `运营总览`
2. `单品分析`
3. `异常商品`
4. `每日汇总`
5. `销售明细`
6. `流量快照`
7. `指标说明`
8. `数据质量`

`单品分析` 使用下拉框选择 SKU，并显示对应商品的销量柱状图、7 日移动平均线和近 30 天浏览量趋势。

### 7.4 PNG 日报

每日生成一张 1920×1080 总览图，用于运营群快速查看。PNG 包含：

- 昨日下单件数和金额。
- 近 7 日销量走势。
- 销量增长和下降商品。
- 高浏览低转化商品。
- 缺货和数据异常数量。

## 8. 页面需求

### 8.1 店铺总览

顶部筛选器：

- 数据日期。
- 商品状态。
- 库存状态。
- 销售区域。

核心指标卡：

- 昨日下单件数。
- 昨日下单金额。
- 近 7 日下单件数。
- 近 30 天浏览量合计。
- 近 30 天转化率中位数。
- 今日售出商品数。
- 缺货商品数。
- 异常商品数。

店铺总览还显示：

- 近 30 日店铺销量柱状图和 7 日移动平均线。
- 销量增长前 10 名。
- 销量下降前 10 名。
- 高浏览低转化前 10 名。
- 缺货和不可购买商品清单。

### 8.2 单品分析

支持通过 SKU、Offer ID、TSIN、条码或商品名称搜索。

商品信息区：

- 商品图片。
- 商品名称。
- SKU、Offer ID、TSIN。
- 当前售价、RRP、基准价和折扣率。
- Offer 状态和库存。

指标卡：

- 昨日下单件数。
- 近 7 日下单件数。
- 近 30 日下单件数。
- 近 30 天浏览量。
- 近 30 天日均浏览量。
- 近 30 天转化率。
- 上一周期转化率。
- 近 30 天退货数量。

商品详情历史区只展示每日销售件数快照，不展示近 30 天浏览量快照，也不使用移动平均线。销售柱图的纵轴必须显示整数数字刻度，柱形悬停信息同时给出指标日期和实际销售件数。

### 8.3 经营四象限

默认以商品在当前 30 天窗口内的浏览量和下单件数中位数为分界：

- 高浏览、高销量：明星商品。
- 高浏览、低销量：转化问题商品。
- 低浏览、高销量：潜力商品。
- 低浏览、低销量：待优化商品。

运营人员可以切换为 25%、50% 或 75% 分位数作为分界。

### 8.4 异常商品

第一版规则：

| 标签 | 默认规则 |
|---|---|
| 销量下降 | 截至指标日的近 3 个自然日下单件数日均值低于近 15 个自然日日均值 |
| 销量上升 | 截至指标日的近 3 个自然日下单件数日均值高于近 15 个自然日日均值 |
| 高浏览低转化 | 近 30 天浏览量不低于商品中位数，转化率低于商品 25% 分位数 |
| 低浏览高转化 | 近 30 天浏览量低于商品 25% 分位数，转化率不低于商品 75% 分位数 |
| 疑似断货 | 总可见库存为 0，且 Offer 仍为可售或近 7 日存在销量 |
| 不可购买 | Offer 状态不是 `buyable` |
| 数据停止更新 | Offer 快照超过 26 小时未成功更新 |
| 未知销售状态 | 出现未配置的 `sale_status` |

所有阈值保存在配置文件中，可修改但不在第一版网页中编辑。

### 8.5 数据质量页

显示：

- 最近一次采集时间和状态。
- 各接口拉取记录数。
- 分页次数。
- API 错误和重试次数。
- 缺失 SKU、重复订单行和未知销售状态。
- 最近一次导出时间和文件路径。

## 9. 数据采集流程

### 9.1 每日任务

默认每天北京时间 08:30 运行，对应 SAST 02:30。

执行顺序：

1. 检查 API 配置和数据库状态。
2. 创建采集批次记录。
3. 分页拉取全部 Offers，并保存当天快照。
4. 重拉最近 7 个 SAST 自然日的 Sales，以捕获状态变化。
5. 按配置选择性拉取 Returns。
6. 去重并写入标准化数据表。
7. 计算每日商品指标和异常标签。
8. 生成离线 HTML、Excel 和 PNG。
9. 写入运行日志和数据质量结果。

### 9.2 初始化回填

首次运行：

- Offers 只能从首次采集日起积累每日快照。
- Sales 默认回填最近 180 天，以 30 天为一个查询分段。
- Returns 默认回填最近 180 天。
- Transactions 第一版不默认回填。

如果 Sales 接口拒绝某个查询区间，采集器自动缩小日期分段并重试，不假定 Sales 存在 180 天上限。

### 9.3 重试与限流

系统读取 API 返回的限流相关响应头，并遵循服务端建议等待时间。若没有可用响应头，采用指数退避：2 秒、5 秒、15 秒，最多重试 3 次。

分页拉取必须一直处理到 `continuation_token` 为空。任何中间页失败时，当前接口采集标记为失败，不发布不完整的当日日报。

## 10. 数据存储设计

### 10.1 数据库选择

正式运行使用本机 MySQL 8.0：

`mysql+pymysql://takealot_app@127.0.0.1:3306/takealot_ops`

使用 SQLAlchemy 数据访问层，不允许业务逻辑散落方言专用 SQL。应用账号只拥有 `takealot_ops` 库的必要权限，ERP 查询使用数据库级只读事务，采集和指标任务使用可写连接。

### 10.2 核心数据表

| 表 | 用途 | 唯一键 |
|---|---|---|
| `collection_runs` | 每次采集状态、时间和错误 | `run_id` |
| `offer_current` | 商品最新状态 | `offer_id` |
| `offer_snapshots` | 每日商品和流量快照 | `snapshot_date + offer_id` |
| `sale_items` | 销售明细和最新状态 | `order_item_id` |
| `return_items` | 退货明细 | `seller_return_id` |
| `daily_product_metrics` | 每日商品汇总指标 | `metric_date + offer_id` |
| `anomaly_events` | 异常标签和解释 | `date + offer_id + anomaly_type` |
| `data_quality_events` | 数据质量问题 | `event_id` |

原始 API 响应以压缩 JSON 形式保存在 `data/raw/YYYY-MM-DD/`，默认保留 90 天；MySQL 标准化数据长期保留。

### 10.3 MySQL 运行规则

- 数据库使用 `utf8mb4`，连接启用 pre-ping 和连接回收。
- 同一时间只允许一个完整采集写任务。
- 网页看板使用 `SET SESSION TRANSACTION READ ONLY` 查询会话。
- 每日导出完成后执行 `CHECK TABLE`。
- 每日通过 `mysqldump --single-transaction` 备份到 `backups/`，保留最近 8 份。

### 10.4 SQLite 退役与迁移

- `data/takealot.db` 只作为一次性迁移源和历史留档。
- `migrate-to-mysql` 只允许导入空目标库，并逐表核对源、目标行数。
- 正式 ERP、采集、指标、竞品、报表和每日任务均不从 SQLite 回退读取。

## 13. 安全要求

1. API Key 只能从环境变量 `TAKEALOT_API_KEY` 读取。
2. `.env`、数据库、原始响应、日志和导出文件不得提交到版本控制。
3. 日志不得输出 API Key、请求认证头或完整个人信息。
4. 离线 HTML、Excel 和 PNG 不包含 API Key。
5. 本地网页默认仅监听 `127.0.0.1`。
6. 第一版只调用读取接口，不调用 Offer 创建或修改接口。
7. ERP 登录会话使用可撤销的 HttpOnly、SameSite=Strict Cookie 与 MySQL 会话记录；初始有效期7天，到期前的有效使用自动把到期时间顺延至最近使用后的7天。同一会话每1天最多续期一次；主动退出以及账号权限、模板、密码或启用状态变化必须立即撤销既有会话。

## 14. 错误处理

| 场景 | 行为 |
|---|---|
| API Key 缺失 | 终止采集，给出明确配置提示 |
| 401/403 | 终止当前任务，不重复无效请求 |
| 429 | 根据响应头等待并重试 |
| 5xx 或网络错误 | 指数退避，最多 3 次 |
| 分页中途失败 | 当日该接口标记失败，不发布不完整日报 |
| 单条记录字段缺失 | 保存原始响应，记录数据质量事件 |
| 未知 `sale_status` | 标记 unknown，不计入有效销量 |
| 导出失败 | 保留数据库结果，单独重试导出 |
| 数据库写入失败 | 回滚当前事务，不留下部分批次 |

## 15. 性能要求

以 500 个商品、两年销售明细为验收规模：

- 店铺总览首次打开不超过 5 秒。
- SKU 搜索和单品切换不超过 2 秒。
- Vue ERP 全部商品图片入口不得直接解码平台全分辨率原图；商品中心、经营坐标、风险与质量、竞品雷达、运营日报及其弹窗/历史区必须使用登录态同源、严格限制来源的缩略图。列表、表格、卡片和小型头图最长边不超过 192 像素，商品中心与风险详情大图最长边不超过 640 像素，并按尺寸缓存转换结果。
- 商品图片必须声明固有尺寸、使用异步解码，长列表图片使用懒加载；经营坐标悬停/复制及其他频繁交互不得重新构建未变化的重复卡片，视口外卡片应跳过布局和绘制，同时仍保留完整数据、搜索和排序能力。
- 每日数据采集完成后 3 分钟内生成全部导出文件，不含 API 限流等待时间。
- Excel 文件建议不超过 30 MB。
- 离线 HTML 建议不超过 20 MB；超过时仅嵌入最近 180 天明细，完整数据保留在 Excel 和数据库。

## 20. 最终决策摘要

1. 第一版同时提供本地网页、离线 HTML、Excel 和 PNG。
2. 四种输出共享同一个数据与指标计算层。
3. 正式数据库使用本机 MySQL 8.0，通过 SQLAlchemy 统一访问。
4. 每日销量按 SAST 日期精确汇总。
5. 流量只展示近 30 天浏览量、日均值和滚动趋势，不伪造每日流量。
6. 系统只读访问 Takealot API，不修改店铺数据。
7. PRD 确认后，通过多智能体完成开发、独立审计和独立测试。
