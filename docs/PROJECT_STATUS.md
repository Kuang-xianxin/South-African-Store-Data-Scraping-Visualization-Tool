## 当前结论

项目主体已完成数据接口、MySQL 存储、指标计算、异常识别、HTML/Excel/PNG 导出和统一 Vue 3 + TypeScript 小型 ERP。八个正式模块为经营总览、商品中心、经营坐标、风险与质量、竞品雷达、运营日报、仅用于 NFT102 续写的报表工作台和管理员可见的用户权限。正式服务监听 `0.0.0.0:8501` 供同一受信任局域网登录，MySQL 8.0 的 `takealot_ops` 数据库仍只允许本机连接；原 Streamlit 看板仅保留为 `dashboard-legacy` 兼容入口。运营日报按北京时间每日10:00至次日10:00建立核对周期，将10:05早间、18:00晚间、次日09:00周期末定时版本、周期内每次手动刷新版本、可重复修改的人工候选值和可撤销的确认最终值分层留痕，并在18:30形成未合并快照。日报落库变化通过登录态服务端事件推送到前端，定时/手动拉取或人工处理后自动刷新矩阵、待办与全局提醒，断线重连补刷新且不覆盖正在编辑的输入。所有采集入口都使用请求级重试、整批新会话重试和绕过异常系统代理的直连备用，只有Offers与Sales完整获取才冻结日报；每次尝试和最终脱敏根因同时保存在文件日志、数据库和页面。漏爬与真实数值冲突已经分离：漏爬自动采用本周期其他可用值并说明原因；近30天浏览量继续保存和展示但不参与冲突判断。同周期版本只比较销量，业务日D的库存优先读取D+1日早间首次完整快照；若早间漏爬或不完整，则由D+1当天10:05后的最新完整成功库存补齐。销量版本差异与前后日报日库存连续性异常统一进入“人工核对待办”，查看后一天时仍保留之前的未完成项。

风险与质量中的销量趋势已改为短长窗口均值比较：截至指标日的近3个自然日日均下单件数低于近15日均值时为“销量下降”，高于时为“销量上升”，相等时不触发；两个窗口均包含指标日，只有完整覆盖15日窗口才判断，已覆盖的空销量日按0件参与平均，历史不足保持未判定，旧的最低销量和涨跌百分比门槛已移除。正式库已按新规则重算2026-07-15至2026-07-29共3676条指标；7月29日是首个完整窗口，产生59条销量下降和21条销量上升，更早日期不保留旧趋势记录。

风险异常详情已增加按类型保存和展示的触发证据，普通提示级“不可购买”不增加重点证据区。销量趋势直接展示截至异常日的15天每日销量柱状图，并保留近3日/近15日日均和差值；高浏览低转化显示异常时近30天浏览量、当前记录销量、近30天转化率及当日分位阈值，低浏览高转化只保留浏览量、销量和转化率三项，不重复展示低浏览边界与高转化边界；本库销量不足30天时明确显示实际记录天数和起止日期；疑似断货显示异常时库存、状态和异常日前7日下单；停止更新显示最近Offer采集时间、实际间隔和阈值；未知销售状态显示具体未配置状态。销量证据使用异常发生日对应的历史逐日指标，不把当前商品指标作为历史判定证据，也不把不足30天的销量伪装为完整窗口。

用户权限页现提供查看、运营、选品、管理员四个等权展示的快速模板，不再把模板当成固定角色。管理员可对每个现有账号逐项增删店铺、竞品、日报、报表、NFT102、刷新和用户管理权限；账号卡片使用连续四边框，消除原用户表分隔线断开。选品模板默认可查看和采集竞品雷达、查看运营日报，但不能处理待办或生成日报 Excel；权限同时由前端导航/按钮和后端逐接口强制执行。无权限模块继续在导航中以“未开放”显示，点击锁定模块或页面内未授权操作统一提示“当前账号该功能权限未开放”。新前端遇到尚未重启的旧后端时会按旧账号模板补齐权限，避免管理员登录后空白；无法识别的登录响应、连接失败和页面脚本异常均显示带重新连接或重新加载入口的错误页。

店铺授权基础已改为无上限的账号—店铺多对多关系。店铺权限目录区分“已接入当前数据”和“已预留待接入”；普通运营可分配任意明确店铺，当前一人两店不是硬编码上限。账号还可独立开启“全部店铺（含未来新增）”，适合管理员和老板：新增店铺后会在下一次会话解析时自动可见，不依赖角色模板或逐账号补配。首个管理员和升级前既有账号保留全店范围；店铺范围、功能权限、密码或启用状态变化都会撤销该账号旧会话。登录后的顶栏已提供账号范围内的“当前查看店铺”选择器；选择待接入店铺时业务区只显示安全占位说明，绝不继续展示`current`店铺数据，管理员仍可进入用户权限配置。当前业务数据仍属于唯一`current`已接入店铺，只分配到待接入店铺的账号会由后端拒绝读取现有单店接口；后续新店正式接入前仍需完成业务表`store_id`分区、采集密钥/任务隔离和真正的逐店业务查询上下文，禁止把当前店铺数据复用于预留店铺。

店铺授权不再作为公共模块的前置条件。竞品雷达和仅含 NFT102 的报表工作台按账号功能权限独立放行，0店铺账号登录后会自动进入第一个已开放公共模块；竞品查看、采集及其共用安全缩略图均不要求店铺范围。经营总览、商品、经营坐标、风险、运营日报、全量刷新和既有店铺报表继续同时校验功能权限与已接入店铺授权。正式账号`pxg`已只读核对为启用、拥有竞品查看/采集权限、`all_stores=false`且0个店铺，本次不修改其权限或店铺关系。

ERP 登录会话现采用7天滑动有效期：成功登录先获得7天，只要到期前继续发起有效请求，就把数据库到期时间和 HttpOnly Cookie 同步延长到最近使用后的7天。同一会话每1天最多续期一次，避免2秒状态轮询造成持续数据库写入；连续7天没有任何有效使用、主动退出或管理员修改账号权限、模板、密码、启用状态时仍需重新登录。

第 7、8 项的代码与合成数据验收已经完成；本机数据库和既有 NFT102 输出已包含真实只读采集结果。本次新增前端入口未主动再生成一份生产日报。

2026-07-28 已增加运营日报登录态实时事件：定时/手动采集及人工处理落库后自动刷新页面待办、矩阵和全局提醒，重连时补刷新；正式修复统一使用 `scripts/restart_erp.ps1` 重启并检查健康状态。同日已在备份 `backups/takealot-20260728-054911-517635.sql` 后删除两件演练商品的137条日报关联数据，直接引用及截止快照 JSON 引用复核均为0。

## NFT102 日常续写流程

1. 运营当天修改并保存生成的 Excel；
2. 第二天把运营最终版上传到看板“`NFT102 日报更新`”页面；
3. 系统原样归档上传基准，识别最新日期，并生成下一日新副本；
4. 页面下载新 Excel 和核对说明，再交给运营继续填写。

该流程不覆盖上传文件。上传基准保存在 `data/nft102-baselines/`，生成结果保存在 `outputs/nft102-daily/YYYY-MM-DD/`。
