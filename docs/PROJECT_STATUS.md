## 当前结论

项目主体已完成数据接口、MySQL 存储、指标计算、异常识别、HTML/Excel/PNG 导出和统一 Vue 3 + TypeScript 小型 ERP。八个正式模块为经营总览、商品中心、经营四象限、风险与质量、竞品雷达、运营日报、报表工作台（含 NFT102 续写）和管理员可见的用户权限。正式服务监听 `0.0.0.0:8501` 供同一受信任局域网登录，MySQL 8.0 的 `takealot_ops` 数据库仍只允许本机连接；原 Streamlit 看板仅保留为 `dashboard-legacy` 兼容入口。运营日报按北京时间每日10:00至次日10:00建立核对周期，将10:05/18:00定时版本、周期内每次手动刷新版本、人工候选值和确认最终值分层留痕，并在18:30形成未合并快照。所有采集入口都使用请求级重试、整批新会话重试和绕过异常系统代理的直连备用，只有Offers与Sales完整获取才冻结日报；每次尝试和最终脱敏根因同时保存在文件日志、数据库和页面。漏爬与真实数值冲突已经分离：漏爬自动采用本周期其他可用值并说明原因；近30天浏览量继续保存和展示但不参与冲突判断。周期内任意版本的订单/库存差异与前后日报日库存连续性异常统一进入“人工核对待办”，页面同时汇总同日报日核对和跨日报日核对，查看后一天时仍保留之前的未完成项。

第 7、8 项的代码与合成数据验收已经完成；本机数据库和既有 NFT102 输出已包含真实只读采集结果。本次新增前端入口未主动再生成一份生产日报。

## 配置和安全状态

- `.env` 应位于项目根目录：`D:\南非店铺数据抓取\.env`。
- `.env` 已被 Git 忽略，CLI 和看板会从项目根目录自动加载，且不会覆盖已经存在的系统环境变量。
- 真实 Key 只能写入 `.env`，不能写入 `.env.example`、日志、报表、测试夹具或聊天记录。
- API Key 由本机项目根目录 `.env` 提供；网页不会显示、保存或回传 Key。只有点击“立即刷新看板数据”、点击 NFT102 生成按钮或每日计划任务运行时才触发只读采集。
- 当前正式数据库是本机 MySQL 8.0；自有店铺、指标和竞品共用 `takealot_ops`。SQLite 文件只作为迁移源和历史留档，不再被运行时读取或自动回退。
- 流量指标只能称为“近30天浏览量”，不能称为精确日流量或访客数。

## NFT102 日常续写流程

1. 运营当天修改并保存生成的 Excel；
2. 第二天把运营最终版上传到看板“`NFT102 日报更新`”页面；
3. 系统原样归档上传基准，识别最新日期，并生成下一日新副本；
4. 页面下载新 Excel 和核对说明，再交给运营继续填写。

该流程不覆盖上传文件。上传基准保存在 `data/nft102-baselines/`，生成结果保存在 `outputs/nft102-daily/YYYY-MM-DD/`。
