## 配置和安全状态

- `.env` 应位于项目根目录：`D:\南非店铺数据抓取\.env`。
- `.env` 已被 Git 忽略，CLI 和看板会从项目根目录自动加载，且不会覆盖已经存在的系统环境变量。
- 真实 Key 只能写入 `.env`，不能写入 `.env.example`、日志、报表、测试夹具或聊天记录。
- API Key 由本机项目根目录 `.env` 提供；网页不会显示、保存或回传 Key。只有点击“立即刷新看板数据”、点击 NFT102 生成按钮或每日计划任务运行时才触发只读采集。
- 当前正式数据库是本机 MySQL 8.0；自有店铺、指标和竞品共用 `takealot_ops`。SQLite 文件只作为迁移源和历史留档，不再被运行时读取或自动回退。
- 流量指标只能称为“近30天浏览量”，不能称为精确日流量或访客数。

## NFT102 日常续写流程

1. 运营当天修改并保存生成的 Excel；
2. 第二天把运营最终版上传到看板“`NFT102 日报更新`”页面；
3. 系统原样归档上传基准，识别最新日期，并生成下一日新副本；
4. 页面下载新 Excel 和核对说明，再交给运营继续填写。

该流程不覆盖上传文件。上传基准保存在 `data/nft102-baselines/`，生成结果保存在 `outputs/nft102-daily/YYYY-MM-DD/`。
