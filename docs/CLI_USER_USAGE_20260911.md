# ERP账号与店铺CLI用量（2026-09-11）

用户确认按ERP登录账号统计，并按操作店铺细分；本次不为每人创建Codex登录，也不恢复个人10%限额。此前解除ERP额外周额度上限的规则继续有效，官方Codex账号额度仍共享。

## 记账与权限

- `erp_cli_usage_events`保存每一次实际CLI回合尝试，以稳定的ERP用户ID和操作时店铺归属。识图、图题融合、竞品标题复核、变体分析及人工触发的重新分析均经过相同入口；读取历史或复用缓存不新增消耗。
- 先持久化尝试再发出请求；账本不能写入时不发起未记账模型调用。区分调用前拦截、已发请求、CLI完成、失败和未确认结束。CLI完成不等同业务分析结构通过。
- 每次收到用量通知立即更新原请求，重复或较旧通知不重复累加。失败、无效JSON和取消保留已知tokens；缺失、空或无效通知保持未知，不能显示成实际消耗0。缓存输入是输入tokens的组成部分，不额外相加。
- 新批次持久化原发起人ID；管理员恢复批次仍归原发起人。旧批次只有用户名时，必须能证明该账号在批次创建时已存在才归属；删除后重建的同名账号、缺失可信时间等不能猜配。
- 默认仅查自己的记录，跨账号与全部账号须`users.manage`权限。接口从认证会话取身份，不接受前端伪造操作者；无店铺数据权限也可读取本人的用量。返回统计和最近20次尝试，不返回提示词、凭据、商品分析内容。
- 今天、近7天、近30天按北京时间自然日统计，另有全部记录。旧分析没有可信操作者，因此不追溯分摊92条历史分析；共享官方额度百分比不能换算为个人百分比。

## 使用入口

标题优化页面右上方“我的 CLI 用量”；账号管理的“全部 CLI 用量”及每个账号行的“CLI 用量”。单账号弹窗按店铺显示请求、输入、输出及已记录tokens。存在缺失用量时显示不完整提示。切换账号立即清空上次数据，迟到响应不能覆盖新账号；离开缓存页面关闭弹窗并清除内容。

## 实现位置

`search_ranking/cli_usage.py`负责逐次写入及汇总；`codex_cli.py`在实际回合收集通知；`service.py`传递店铺商品操作上下文；`batch.py`保留批次所有者；`erp/web.py`绑定认证用户及汇总权限；前端共用`CliUsageDialog.vue`。
