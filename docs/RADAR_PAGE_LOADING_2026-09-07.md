# 选品雷达整页加载修复（2026-09-07）

## 现象与范围

用户在第一轮数据库读取优化后仍报告两个分区整页没有明显加快。本次针对真正竞品、自有商品列表的首屏显示、完整响应传输和反复重算，不改变商品数据及计算口径。公司网卡、DHCP、路由器、网关、DNS、数据库服务及蓝版环境不调整。最终仅在本机当前 Windows 用户的系统代理例外中追加公网 ERP IP，保留雪莲开启状态、代理服务器及全部原例外。

公网登录态 Chrome 实测旧版真正竞品响应解压后 15,441,350 字节、自有商品 8,392,245 字节；gzip 后约 1,124,213 / 620,145 字节。真正竞品完整请求样本为 3.25 / 17.30 / 5.37 / 7.08 / 2.57 秒，自有商品为 2.04 / 7.55 / 7.16 秒。活动采集不断改变数据版本，先前缓存命中样本不能代表日常整页体验。

## 修改

- 两个列表分别启动读取、分别显示完整结果，可见分区先发起；页签与加载状态无需等两个请求全部完成。
- 新增权限、授权店铺、日期和后端源码版本隔离的完整响应缓存。数据修订变化时可先返回至多 15 分钟前的完整读取结果，再由一个后台读取线程生成新结果；页面明确显示上次读取时间与正在更新。权限/所有权边界变化、跨日、超时或源码变化不复用旧结果。
- 缓存边界按每次验证后的实际账号权限生成，不用全局账号最后登录修订清空所有人的预览；单 PLID 详情仍用原投影缓存，不能挤占整页缓存。
- 默认 API 调用仍等待当前结果；只有页面显式 `prefer_cached=true` 才使用预览。刷新失败保留已展示内容和错误提示；退出登录、请求取消、店铺或日期变化时拒绝过期请求回填。
- 响应只序列化一次并准备 gzip/Brotli，无损保留所有字段。私有条件缓存使用弱 ETag、`Vary: Accept-Encoding, Cookie, X-Store-Code`；相同内容可返回 304。权限验证仍逐请求执行。
- 内存保留最多 6 份完整结果，磁盘最多 12 份 gzip 缓存，原子替换、校验哈希与体积上限；重启可以重用未过期且代码边界一致的结果。缓存文件位于 `data/runtime-cache/radar-pages`，不是数据库备份。
- `fast-reads` 可选依赖增加 Brotli；绿版安装 Brotli 1.2.0，原生 MySQL 只读驱动继续使用。无数据库结构和业务写入变化。
