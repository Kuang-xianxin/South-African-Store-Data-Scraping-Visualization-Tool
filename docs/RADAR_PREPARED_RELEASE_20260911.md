## 原因与对应修改

此前恢复保留了完整旧预览，但首次新范围仍需整理1090条自有链接。实际无缓存读取曾耗时57.930秒，严格重算曾耗时71.188秒；旧公网记录中出现75～208秒的上游等待和499。因此旧预览修复缓解了已有范围刷新，却没有消除新范围首次计算，也没有改变先停服务再启动的发布顺序。

1. **同一有效店铺范围复用结果。** 之前缓存边界包含完整账号身份，相同店铺权限的两个人仍会分别准备。现在每次请求先重新验证当前账号、店铺权限和有效店铺集合，再按相同集合共享分页结果。个人池在共享读取后按用户筛选；禁用账号、撤销店铺和全局自有身份屏蔽继续生效。测试覆盖同范围复用和权限撤销。
2. **按实际贡献店铺增量更新。** 之前所有选中店铺的版本都进入每条商品指纹，一个店铺变化可能使无关商品重算。现在每条商品只包含当前及历史贡献店铺的版本，历史上有报价、后来删除或迁移的店铺也参与失效判断。产品主数据、历史修订、身份变化、模型、实际日期区间和官方销量跨日仍会正确触发更新。
3. **访问之前准备常用范围。** 后台枚举当前有效用户的全部、当前、运营店铺范围并去重，每60秒重新发现新增范围；同时准备默认日期和网页先读取的实际公共日期区间。本次必需24个范围，含22个自有范围、2个真正竞品范围。一个完整新版本完成前继续提供带原生成时间的完整旧结果。
4. **持久化结果和运行实例隔离。** MySQL仍为事实来源，SQLite只保存可重建的分页卡片。每个源码版本有独立文件；备用服务还使用发布目录中的私有副本，避免同版本两个进程写同一个SQLite文件。复制通过SQLite在线备份读取完整已提交快照，旧主进程退出、端口释放后才安装到主服务目录。每分区单线程、每批32条、每文件约128MiB、每分区32个范围上限保留。历史版本文件保留，以上为单文件上限，不是全部历史版本的总磁盘上限。
5. **固定已经验证的运行源码。** 共享工作区存在其他任务未完成的BLUE、CLI用量统计改动，直接从那里启动会混入未经本轮验证的代码。已从原基线5b93631创建隔离工作区，只带入本次改动；运行源码与原数据目录分开，后续普通重启读取已验证源码位置。

## 正式重启现在怎么执行

原服务继续提供访问 → 备用只读服务准备全部必需范围 → 本机真实登录检查24项 → 公网允许的读取临时接入备用服务 → 公网真实登录检查24项 → 原采集完成当前商品并落盘、在途响应完整发送 → 停止旧主进程 → 安装已准备缓存并启动正式服务 → 核对实际源码版本与健康 → 公网切回并等待备用响应结束 → 回收备用进程及隧道。

- 备用8511只允许GET/HEAD读取首页、静态资源、健康、登录状态/当前会话、日期范围、真正竞品和自有链接列表。其他路径不桥接；任务状态GET也不能被当作无副作用读取。POST等写方法保持原入口，不复制或重放。
- 备用登录校验只读正式数据库中现有会话及当前用户，不续期、不复制登录数据、不改变正常BLUE隔离规则。验证使用短期会话，凭据仅保存在内存，结束后精确清理。
- 临时SSH18507经过既有GREEN公网Nginx入口；只修改指定GREEN配置文件，校验修改前哈希、Nginx语法和重载传播，回退幂等且拒绝覆盖其他任务的并发配置修改。
- 发布租约停止续期15秒后自动失效。采集每完成并保存当前商品后暂停取下一项；HTTP排空计数直到完整响应体发送。持续事件流允许重连。准备或切换前验证失败时保留健康旧服务。
- 首次旧版本迁移显式使用过 `-AllowLegacyDrain`，只在确认落盘断点后冻结并复核；最终23:11发布使用正常排空接口，无此兼容开关。后续常规重启不需要它。
