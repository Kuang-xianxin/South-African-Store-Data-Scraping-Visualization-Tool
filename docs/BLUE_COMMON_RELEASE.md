## 可重复流程

1. 确认并发任务完成，绿版已发布前端与后端配套；保留两蓝现有文件清单、原批次和交付日志证据。
2. `blue_sync_release.py build --project <项目目录> --archive <新包.zip>` 递归遍历当前前端入口引用，冻结 SHA256 清单，构建期间源码变化立即拒绝。本次另有BLUE组件时在独立目录构建，使用 `--frontend-dist <已验证的独立构建目录> --with-blue-runtime`，不改绿版线上入口。
3. 用 `inspect --archive <包> --sha256 <哈希>` 对照每机实际文件。蓝根目录 HA 包装单独核验，通用包禁止覆盖。
4. 本次兼容增量由 `schema` 只经已核验主机蓝101/3307/UUID连接新增 `erp_data_revisions` 和已确认缺少的读取索引。两 worker 仅补标记表 INSERT/UPDATE；SELECT沿用已有只读权限。权限变更不复制账号元数据，数据库角色不变。
5. 两端队列无执行中任务且无待补交结果，普通蓝批次已经停止、原成功/终态断点完整保留后，使用 `install_blue_common_release.ps1` 重载现有 BLUE web/worker。脚本先备份差异文件，仅覆盖包内文件、最后发布入口；保留旧哈希资源与 app 运行目录。不能使用绿重启脚本。
6. 两端全部包内文件 SHA 一致；复核源码加载、所有模块登录读取、新功能、共享入口与蓝隔离、MySQL复制、原断点及绿进程连续性。本次全量能力须两worker心跳均带 `durable-v1 full-v1` 后才开放入口，旧1–20接口和旧blue-web任务身份继续兼容。明确区分资源检查、接口验收和浏览器验收。

同步工具不会定时运行，也不自动复制尚未验证的工作区。后续每次通用发布应重复此流程并记录两节点版本；离线或被取消的节点须记为待同步，不能宣称全部完成。
