# 发布审计报告

审计时间：2026-07-21 13:01（Asia/Shanghai）  
审计范围：Takealot 只读 API、分页完整性、数据持久化、指标口径、四种输出、密钥保护、本地看板、每日调度与备份。  
审计数据：完全合成的 10 SKU / 31 天数据集，不包含真实店铺信息。

## 审计结论

在合成数据和本机运行边界内，项目满足发布前的功能、口径和安全要求。API 客户端只允许 HTTP GET；分页失败不会发布不完整 Offer 快照或日报；数据库、独立 HTML、Excel 与看板均使用同一指标服务；生成物和日志未发现测试密钥或 `X-API-Key` 认证头。

真实 Takealot 店铺只读联调尚未执行。该步骤必须由用户在本机 `.env` 中配置 Key 后单独完成。

## 验收数据覆盖

统一合成场景包含：

- 10 个 SKU；
- 31 个自然日、共 310 条 Offer 快照；
- 一个 Offer 的 31 天流量全部缺失；
- 一个最终库存为 0 的 Offer；
- 两笔跨 SAST 日界线的订单；
- 同一订单项从计入状态更新为排除状态；
- 一个未知销售状态；
- 重复执行同一批采集与指标重建。

## 核心检查

### API 只读安全

- `TakealotClient` 的请求边界拒绝非 GET 方法。
- 第一版只调用 `/offers`、`/sales`，并保留可选只读 `/returns`。
- API Key 只进入 `X-API-Key` 请求头，不进入 URL。
- 401/403、429、5xx、传输异常和数据转换异常均使用脱敏错误。
- 分页 continuation token 缺失或为空时正常结束；非法 token 和非法响应结构会失败关闭。

### 分页与发布原子性

- Offer 或 Sales 第二页失败时，采集结果标记失败。
- Offer 当前表、当日快照和销售表不会保留半批数据。
- `daily-run` 在采集失败后不会调用报表发布。

### 幂等性

- 同一 10 SKU / 31 天输入重复写入后，业务表行数和内容 SHA-256 保持一致。
- 审计发现未知销售状态事件曾使用随机 UUID，导致重复重建内容哈希变化；现已改为由日期、Offer 和状态集合生成确定性 UUID5，并增加模块级与端到端回归测试。

### 跨输出一致性

- 数据库、独立 HTML 内嵌 JSON 和 Excel“销售明细”中的 10 个 SKU 下单件数汇总完全一致。
- 310 条数据库流量快照与合成 Offer 源值逐条一致，包括缺失值。
- Excel 可由 OpenPyXL 连续打开两次，八个工作表尺寸有效，图表及 drawing relationship 存在。
- HTML 在 Playwright 中从 `file://` 打开时只产生本地文件请求，没有 HTTP(S) 依赖。

### 密钥与输出扫描

- 扫描范围包括合成 HTML、Excel 和 CLI 日志。
- 未发现合成测试密钥 `release-fixture-super-secret`。
- 未发现 `X-API-Key` 字符串。
- `.env`、数据库、日志、备份和正式导出目录均由 Git 忽略。
- 仓库只保留明显标注的模板值和测试夹具密钥，不包含真实 Key。

### 流量口径

- `page_views_30_days` 统一展示为“近30天浏览量”。
- 日均值明确是 30 天滚动窗口除以 30。
- 相邻快照差值称为“30天浏览量窗口净变化”。
- 不使用“精确日流量”或“访客数”，缺失值不补零。

### Windows 本地边界

- 看板命令强制传入 `127.0.0.1` 和校验后的端口。
- 非回环地址及非受支持同步驱动会友好失败；正式数据库只连接本机 MySQL。
- Windows Job Object 使用 kill-on-close；外层启动器被终止后，所有后代进程和监听端口均消失。
- 计划任务脚本不会自动安装，只有运营人员明确运行时才创建任务。

## 已修复问题

1. 看板启动器被外部终止后，`uv` Python 后代可能继续监听端口：已用 Windows Job Object 修复并加入真实运行测试。
2. 未知状态质量事件使用随机 ID，重复重建不完全幂等：已改为确定性 UUID5。
3. `.env` 之前只是模板、程序不会自动读取：现由项目根目录显式加载，系统环境变量优先。

## 剩余风险与上线前动作

- 尚未使用真实 API Key 验证官方生产响应；用户配置 Key 后只执行只读联调。
- `config/sale_status_rules.yaml` 当前不预设真实销售状态。首次真实采集后必须根据数据质量提示，由运营人员确认哪些状态计入或排除，不能由程序猜测。
- 2026-07-23 已完成 MySQL 迁移补充验收：12张表4204行逐表一致，ERP MySQL 查询会话拒绝写入，`CHECK TABLE`、报表读取及 `mysqldump --single-transaction` 备份通过；旧 SQLite 只保留为迁移源留档。
- PNG 导出依赖本机 Playwright Chromium；缺失时 HTML 和 Excel 仍会保留，并明确报告 PNG 未生成。
- API 官方字段或销售状态未来可能变化，需要通过未知状态和响应校验错误持续暴露，而不是静默吞掉。
