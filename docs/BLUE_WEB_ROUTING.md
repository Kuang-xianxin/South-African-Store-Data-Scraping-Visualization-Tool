## 请求如何分配

| 请求 | 规则 |
| --- | --- |
| 页面资源、普通查询、账号/店铺修改、个人池操作、物流关联、监控修改 | 按资源分流；鉴权、CSRF及店铺权限继续由原应用验证 |
| 共享双机采集的开始、停止、继续、进度 | 两端均访问主机蓝库的共享队列，可动态分流；启动/继续前发现旧本地批次活动则拒绝，爬虫领取规则不变 |
| 新增监控链接 | 无活动旧本地批次时动态分流；需要加入该本地批次时发到其归属节点 |
| 标题分析新任务、全店刷新、导出生成、列表预览 | 两端状态新鲜且相关控制器空闲时为新操作选择节点，先持久预约120秒，防止同时首次请求落到不同机器 |
| 暂停、停止、继续、任务状态、预览令牌提交 | 跟随该控制器的持久归属，暂停/中断也保留归属；节点离线不自动升主或重放写操作 |
| 文件列表与下载 | 根据受限文件目录的元数据找到实际持有节点；保留旧日期文件的位置，生成中不返回半成品，最新已知持有节点离线时不回旧副本 |
| 登录限流、门户OTP及一次性操作令牌 | 保持进程归属，避免分散限流或丢失临时令牌；BLUE原本关闭的平台写入开关保持 |

资源规则沿用第一版：每5秒采样物理可用内存、可提交空间、活动HTTP数及响应延迟；12秒未更新就退出候选。普通浏览器路由Cookie至少保持60秒，另一端综合评分需高出35%才迁移后续请求；正在执行的请求不搬迁。两端当前前端SHA必须与笔记本参照版本一致。

本地任务的归属单位对应当前应用的全局控制器，例如搜索批次、旧本地采集、全店刷新；这些接口原本就只暴露一个当前任务，未改造成无限并行任务池。新任务启动可选节点，已有任务控制不能因为内存变化改去空的控制器。首次升级沿用原公网笔记本的历史归属。原笔记本本地批次文件仍存在，主机无此文件，不复制或清除它。

局域网直接登录、普通读取、共享数据库写入及共享双机队列接口保留。依赖本地状态的变更若绕过公网协调入口，会返回409并提示从蓝版公网入口操作，防止两个入口并行创建相互看不到的控制器。

## 数据与运行边界

数据库仍主机101单写。笔记本只读ERP引擎每次取得主库当前GTID边界后，核验102身份、种子、双只读及GTID覆盖；没追上或连接失败回101只读事务，主库不可核验时不读旧备份。没有物理内存合并、数据库自动升主或爬虫让出资源机制。

归属保存在腾讯服务的/var/lib/takealot-blue-routing/ownership.json，重启继续读取；这里只保存控制器节点、短期预约和修订号。实际业务任务、队列、文件均留在原位置。节点每5秒上报不含正文的容量/控制器状态/文件参数哈希；完成操作时向Tailnet 100.72.100.10:18504/snapshot推送一次受密钥保护的元数据，失败由下一次心跳补上，不重试业务动作。启动标记与单调序号防止旧心跳覆盖较新状态。该Tailnet监听只接受受保护的快照POST，不开放路由决定或status；Nginx仍通过loopback18504获取路由。

成功写操作发布修订后，后续请求使目标节点重新读取数据库版本并清理通用读取缓存。业务正文、登录Cookie、密钥和文件内容不写入调度状态。文件发现只允许BLUE app下的exports和outputs/nft102-daily及既有文件名规则，不接受任意本地路径。

两端网页仅更新blue_web_capacity.py、blue_web_inventory.py、blue_web_routes.py；blue_web.py、blue_runtime.py、blue_read_replica.py、业务service.py、前端和爬虫代码保持本轮前的发布基线。后续业务同步必须验证Inventory依赖的控制器字段，保留BLUE副本钩子。另一任务的Sol及竞品标题语义分析蓝版限定包仍未安装，本轮不把其视为已支持。
