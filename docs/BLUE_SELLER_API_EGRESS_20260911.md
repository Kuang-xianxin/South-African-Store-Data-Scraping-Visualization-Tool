# BLUE Seller API 主机优先

2026-09-11 10:44 已在腾讯蓝版入口启用 `main-first-v1`。

## 当前行为

- 经蓝版公网启动的订单、库存全店刷新（`POST /api/erp/refresh`）优先在主机节点执行，不再按内存、负载或浏览器路由 Cookie 选择出口。整次刷新内的 Offers、Sales、Returns、指标和报表仍使用原流程。
- 主机容量探测连续失败至少两次，且原心跳已超过12秒，才允许为新的空闲刷新选择笔记本。容量低、前端版本不匹配或 Seller API 返回401/403/429不作为轮换出口的理由。
- 每次转发启动请求前持久预约120秒。必须再收到该节点经过鉴权的空闲清单，才能确认预约对应工作已结束；计时到期或公网请求超时本身不能证明后台结束。
- 正在执行、结果未确认或旧节点最后仍报告忙碌的刷新保持原归属；不自动重放整次刷新。笔记本执行中即使主机恢复也继续留在笔记本，确认空闲后下一次优先回主机。
- 刷新状态读取跟随活动归属；两端都空闲且原请求已确认结束时，状态入口同样回主机。已确认空闲与未确认预约均随原version 2归属文件持久保存，路由服务重启不会清除这些证据。

本次调整的是正常蓝版公网全店刷新的执行节点。没有改普通网页分流、双机竞品爬虫公平领取、模型代理、Seller API GET限制、平台登录开关或手工CLI命令；也没有把整个操作系统的网络统一改代理。
