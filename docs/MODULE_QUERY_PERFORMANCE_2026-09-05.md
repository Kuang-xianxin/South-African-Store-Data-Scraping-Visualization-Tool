## 改动

- 总览由数据库汇总每日销量，只取最新指标、成功Offer快照和对应日期异常身份，不再加载无关完整历史、质量事件；保留原日期和缺失规则。
- 多店流量用真实店铺/run_id组合查询，新增覆盖索引`ix_daily_report_observations_store_run_views(store_code,run_id,page_views_30_days)`，正式3306/takealot_ops采用INPLACE/LOCK=NONE，2.416秒完成；EXPLAIN由旧索引遍历变为新索引range/Using index。模型和幂等升级同步，不回填业务记录。
- 关键词清单只读取5列标题历史，签名缓存最多4096项，保留全部标题变更。清单每页挂载60卡，搜索/筛选覆盖全部，清单与详情独立结束加载。
- 坐标只传回30日窗和每Offer首末指标；从完整库存历史在SQL定位最后增加的相邻已知库存对。六店库存传输行数60092→1054、指标69062→52572；保留未知库存、历史间隔、旧补货和最早记录。日期稳定排序消除同分商品随无关历史行数跳动。
- 异常商品减少DataFrame/字典转换，外层按完整授权范围缓存，内层店铺销售/库存历史与评论变化分开复用；连续无销量天数不截断。
- 物流复用只读连接池，删除新Session解码后的多余深拷贝，同一运单编号只规范化一次；普通GET按版本缓存，人工同步仍执行原路径并失效缓存。
- 配柜快照使用窄列与raiseload，变体只读身份、评论只读日期；补货、利润、库存观察规则不变。
- 关键词/搜索大响应使用shallowRef；搜索底部词库接近视口才读取，手动入口与批次状态轮询保留。复用既有Gzip与同键并发请求合并，未加Redis或独立中间件服务。

## 更新与开销边界

注册版本的投影最多48项/180秒，未注册版本仍20秒；授权先于缓存，键包含真实店铺集合、日期、范围、参数。版本查询共享2秒轻量缓存，相关店铺/域写入使缓存失效，搜索资格额外采用15秒时间分段。异常历史最多12项/180秒，仅复用未变店铺数据。

沿用15秒检查版本、仅更新当前可见模块、竞品最短30秒，不是每15秒查询全部模块。物流版本增加店铺Offer/SKU来源。手写SQL绕过应用事务标记仍由TTL兜底，不属于立即通知范围。缓存/索引有有限内存、磁盘和索引写入开销，未增加采集并发或上游访问频率。
