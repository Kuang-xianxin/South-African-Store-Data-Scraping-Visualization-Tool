`blue_web.py`只有存在精确`state/writable-test.json`才加载可写模式；当前没有此标记，原网页不变。`blue_worker.py`使用蓝专用账号和本机127.0.0.1:7897代理；worker默认验证器保持旧行为，新增可注入验证器供蓝入口严格检查id101，不能复用旧绿worker启动命令。

`blue_activation.py`和`activate_blue_writable.ps1`预检部署文件、蓝网页/worker账号与复制，再只操作蓝网页和蓝worker任务，不重启MySQL、不自动升笔记本为主。新启动器与worker代码尚未部署启用，目前没有常驻蓝worker。

## 恢复工作顺序

1. 用户允许后再发主机UAC，安装仅笔记本IP可访问的LAN13317，核验TLS和延迟；不动绿3306/8501。
2. 白名单导入所需Seller/W8和模型配置，说明缺失配置；不复制根.env、Portal cookies、旧断点或绿备份地址。
3. 将任务审查的启动器及worker增量部署到两机并核对哈希，不整包覆盖共享工作区其它任务的修改。
4. 重验蓝副本健康/一致性，启用固定主机蓝写主；以独立蓝测试记录验证增改删与复制，失败不开放网页。
5. 只重启两端蓝网页，安装/启动蓝worker，验证原8502/8443及新8503入口。完整集成验收通过前不能称已交付。
6. 接通正常页面与共享队列；现有网页/09:00 runner尚未改为共享队列。进程内批次控制、断点和文件仍须跨节点协调，worker测试不能替代这一步。
